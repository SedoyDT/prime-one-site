# tmux и tmuxinator: сценарии использования

Конкретные рабочие ситуации вместо перечисления команд — формат «как пользователь, я хочу X, поэтому использую Y». Основной трек с объяснениями — [[karta-tmux|tmux и tmuxinator: от сессий к автоматизации проектов]].

## Сценарий 1: SSH оборвался — работа не потеряна

*Как разработчик, работающий по SSH на удалённом сервере, я хочу, чтобы обрыв соединения не убивал запущенные процессы и не закрывал открытые файлы.*

**Решение:** работать внутри именованной tmux-сессии, а не напрямую в SSH-шелле:

```bash
tmux new -s work
```

Если соединение оборвалось — сессия продолжает жить на сервере. После переподключения по SSH:

```bash
tmux attach -t work
```

Всё на месте: открытые панели, история команд, запущенные процессы. То же самое работает и при намеренном `prefix d` (detach) — разницы для tmux нет, отцепление явное или из-за обрыва связи выглядит для сессии одинаково.

## Сценарий 2: Поднять всё рабочее окружение одной командой

*Как разработчик, я хочу каждое утро одной командой получить редактор, окно с логами сервера и свободный шелл — вместо того чтобы вручную пересобирать одни и те же окна и панели.*

**Решение:** один раз описать проект в `~/.config/tmuxinator/<name>.yml` — как в [[ustanovka-i-proekty|туториале про tmuxinator]] — и дальше:

```bash
tmuxinator start myproject
```

Вся раскладка окон и панелей, команды в каждой панели и рабочая директория — воспроизводятся идентично каждый раз, без ручных действий.

## Сценарий 3: Выполнить одну и ту же команду сразу в нескольких панелях

*Как разработчик/админ, я хочу набрать команду один раз и увидеть её выполнение одновременно в нескольких панелях (например, на нескольких серверах в разных панелях по SSH).*

**Решение:** встроенная в tmux команда синхронизации панелей — не привязана к отдельной клавише в этом конфиге, набирается вручную (или закрепляется за своим биндом при желании):

```
:setw synchronize-panes on
```

Дальше ввод в любой панели окна дублируется во все остальные панели того же окна. Обязательно выключить после использования, иначе случайная команда попадёт сразу везде:

```
:setw synchronize-panes off
```

## Сценарий 4: Не повторять настройку окружения в каждой панели проекта

*Как разработчик, я хочу, чтобы во всех панелях проекта автоматически была нужная версия интерпретатора/окружения, не прописывая это в команде каждой панели отдельно.*

**Решение:** `pre_window` в yml-конфиге проекта — выполняется перед командой каждой панели каждого окна:

```yaml
pre_window: rbenv shell 2.0.0-p247
```

Одна строка в конфиге вместо повторения в `panes:` каждого окна — см. полный пример в [[ustanovka-i-proekty|туториале про tmuxinator]].

## Сценарий 5: Быстрый переключатель сессий по имени папки проекта (рецепт)

*Как разработчик с десятком активных проектов, я хочу одним сочетанием клавиш прыгнуть в сессию нужного проекта — создав её, если её ещё нет, или переключившись, если уже есть.*

Это **не** то, что уже настроено на этой машине сейчас — рецепт, который стоит собрать самому, известный как паттерн «tmux-sessionizer» (популяризован ThePrimeagen). Идея: bind на всплывающее окно (`display-popup`) с fzf-подбором директории проекта, дальше — `tmux new-session`/`switch-client` с именем сессии по имени папки:

```
bind-key f display-popup -E "фд-или-find-по-проектам | fzf | xargs -I{} tmux-sessionizer-скрипт {}"
```

где `tmux-sessionizer-скрипт` — отдельный shell-скрипт, который создаёт сессию с именем папки, если её ещё нет (`tmux new-session -d -s имя -c путь`), и переключается на неё (`tmux switch-client -t имя` или `tmux attach -t имя`, в зависимости от того, внутри tmux вызов или снаружи). Отдельная задача, если решите собрать — протестировать сначала вручную по шагам, потом завернуть в один бинд.
