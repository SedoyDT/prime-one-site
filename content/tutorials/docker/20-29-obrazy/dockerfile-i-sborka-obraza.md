# Dockerfile и сборка образа

Уровень сложности: ~25/100. Нужен установленный Docker (см. [[ustanovka-i-pervyy-konteyner|предыдущий туториал]]) и текстовый редактор.

**Предполагается:** умение запустить контейнер из готового образа (`docker run`). Дальше речь о том, как собрать образ самому.

## Зачем свой образ

Готовые образы (`ubuntu`, `nginx`, `python`) — это чистая система без вашего кода. Чтобы упаковать своё приложение вместе со всем, что ему нужно, — пишется **Dockerfile**: текстовый рецепт сборки образа.

## Минимальный пример

Создайте рабочую папку и два файла.

`hello.sh`:

```sh
#!/bin/sh
echo "Привет из контейнера, $(hostname)!"
```

`Dockerfile` (без расширения, именно так называется файл):

```dockerfile
FROM alpine:3.20
COPY hello.sh /hello.sh
RUN chmod +x /hello.sh
CMD ["/hello.sh"]
```

Построчный разбор — это и есть весь набор инструкций, нужный на старте:

- **`FROM alpine:3.20`** — базовый образ, с которого начинается сборка. Alpine выбран не случайно: это дистрибутив Linux размером ~7 МБ (для сравнения, Ubuntu — сотни МБ), удобен как основа для маленьких образов.
- **`COPY hello.sh /hello.sh`** — скопировать файл с диска (из папки сборки) внутрь образа.
- **`RUN chmod +x /hello.sh`** — выполнить команду **во время сборки**, результат (файл со снятым флагом "не выполняемый") попадает в образ.
- **`CMD ["/hello.sh"]`** — команда, которая выполнится, когда из образа запустят контейнер **без явной команды в конце `docker run`**. В отличие от `RUN`, `CMD` не выполняется при сборке.

## Сборка

```
docker build -t hello-image .
```

- `-t hello-image` — тег (имя), под которым образ будет виден в `docker images`;
- `.` — контекст сборки: папка, файлы из которой доступны для `COPY`/`ADD` (в данном случае — текущая).

Docker построчно выполняет инструкции и кэширует результат каждой (об этом кэше подробно — на уровне 50–59). Итог — новая запись в `docker images`.

## Запуск

```
docker run --rm hello-image
```

Должно напечататься `Привет из контейнера, <какой-то hex>!` — hostname контейнера по умолчанию равен его ID.

## Теги и версии

Без явного тега Docker подставляет `latest` — это просто ещё одна строка, а не «самая свежая версия» в каком-то особом смысле:

```
docker build -t hello-image:v1 .
docker images
```

`docker images` покажет `hello-image` с тегами `latest` и `v1` — оба указывают на один и тот же образ, если он не менялся между сборками. Явные версии (`v1`, `v2`, дата, git-хэш) вместо голого `latest` — то, что отличает воспроизводимый деплой от «а на проде какая версия вообще стоит».

## Изменить и пересобрать

Поменяйте текст в `hello.sh`, пересоберите с тем же тегом:

```
docker build -t hello-image:v1 .
docker run --rm hello-image:v1
```

Новый вывод покажет, что изменилось именно содержимое образа, а не поведение самого Docker.

## Проверка себя

Измените `Dockerfile` так, чтобы `CMD` печатал ещё и текущую дату (`date`), пересоберите и запустите. Если вывод содержит и приветствие, и дату — Dockerfile понят правильно.
