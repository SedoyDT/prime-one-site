# Установка Docker и первый контейнер

Уровень сложности: ~15/100. Нужен терминал и права на установку ПО.

**Предполагается:** понимание разницы между образом и контейнером — [[chto-takoe-konteynerizaciya|Что такое контейнеризация]]. Если Docker уже установлен и `docker ps` работает без ошибок — можно смело переходить к [[dockerfile-i-sborka-obraza|следующему туториалу]].

## Установка

Официальный способ зависит от системы:

- **Linux** — самый быстрый путь для теста: `curl -fsSL https://get.docker.com | sh` (официальный установочный скрипт Docker). После установки Linux-пользователю нужно добавить себя в группу `docker`, иначе каждую команду придётся запускать через `sudo`: `sudo usermod -aG docker $USER`, затем перелогиниться.
- **macOS / Windows** — Docker Desktop с сайта docker.com, дальше всё через графический установщик.

Проверка, что всё встало:

```
docker version
```

Команда покажет две части — версию клиента (Client) и версию демона-сервера (Server). Если Server не отвечает — демон не запущен (на Linux: `sudo systemctl start docker`; в Docker Desktop — просто открыть приложение).

## Первый контейнер

```
docker run hello-world
```

Что произошло по шагам, которые Docker печатает в вывод:

1. Docker поискал образ `hello-world` **локально** — не нашёл.
2. Скачал его из Docker Hub (публичного реестра образов) — это называется `docker pull`, `run` делает его автоматически при отсутствии образа.
3. Создал из образа контейнер и запустил его.
4. Контейнер напечатал приветственное сообщение и завершился — его единственная задача была это сделать.

Повторный запуск той же команды пройдёт без скачивания — образ уже лежит локально:

```
docker images
```

покажет `hello-world` в списке.

## Интерактивный контейнер

`hello-world` работает и сразу останавливается. Чтобы оказаться *внутри* контейнера с полноценным терминалом:

```
docker run -it ubuntu bash
```

- `-i` (interactive) — держать стандартный ввод открытым;
- `-t` (tty) — выделить псевдотерминал, чтобы ввод/вывод выглядел как обычная консоль;
- `ubuntu` — образ;
- `bash` — команда, которую нужно выполнить внутри контейнера вместо команды по умолчанию.

Внутри — обычный Ubuntu-шелл. Проверьте, что это изолированная среда:

```
cat /etc/os-release
ls /
exit
```

`exit` завершает `bash`, а вместе с ним и сам контейнер — контейнер жив ровно пока жив его главный процесс.

## Что осталось после выхода

```
docker ps
```

покажет пустой список — контейнер остановлен, значит, не "запущенный" (running). Но он не исчез:

```
docker ps -a
```

`-a` (all) покажет все контейнеры, включая остановленные. Это ловушка новичка: каждый `docker run ubuntu` создаёт **новый** контейнер, а не переиспользует старый. После десятка экспериментов `docker ps -a` покажет десяток мёртвых контейнеров, занимающих место на диске.

Убрать конкретный:

```
docker rm <container_id>
```

Убрать все остановленные разом:

```
docker container prune
```

Чтобы контейнер не оставлял следов сам, можно сразу запускать с флагом `--rm` — он удалит себя после остановки:

```
docker run --rm -it ubuntu bash
```

## Проверка себя

Запустите `docker run --rm -it alpine sh` (Alpine — минималистичный образ, вместо `bash` в нём обычно только `sh`), внутри выполните `whoami` и `hostname`, выйдите через `exit`, и убедитесь через `docker ps -a`, что контейнер не остался в списке благодаря `--rm`.
