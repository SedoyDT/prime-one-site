# Vim и LazyVim: сценарии использования

Не туториал по командам, а набор конкретных рабочих ситуаций — «как пользователь, я хочу сделать X, поэтому использую Y». Формат каждого сценария: роль/цель/результат, затем конкретное решение теми же командами, что и в основном треке — [[karta-vim|Vim и LazyVim: от основ к LazyVim]].

## Сценарий 1: Безопасно переименовать переменную во всём файле

*Как разработчик, я хочу переименовать переменную во всём файле, но не вслепую — чтобы не задеть похожее по названию, но не то же самое.*

**Решение:**

```
:%s/old/new/gc
```

Тот же `:%s/old/new/g`, что и в основах поиска-замены, только с добавленным флагом `c` (confirm) — Vim останавливается на каждом совпадении и спрашивает `y/n/a/q/l`: подтвердить, пропустить, подтвердить всё, выйти, подтвердить и выйти. Медленнее автоматической замены, зато безопаснее там, где совпадения не все однозначны.

## Сценарий 2: Применить одинаковую правку к полусотне похожих строк

*Как разработчик, я хочу быстро применить одну и ту же многошаговую правку к 50 однотипным строкам, не переписывая каждую руками.*

**Решение:** записать макрос один раз на первой строке, воспроизвести его на остальных:

```
qa
... правка на одной строке ...
q
50@a
```

Или, если правку нужно применить ко **всем** строкам файла разом, без ручного подсчёта:

```
:%normal @a
```

`:%normal @a` выполняет `@a` на каждой строке файла — не нужно знать точное число строк заранее. Помнить про ловушку макросов: если строки структурно разные, движения внутри макроса могут «доехать не туда» — тогда надёжнее `:%s` с regex.

## Сценарий 3: Сравнить две версии файла бок о бок

*Как разработчик, я хочу увидеть построчные отличия между двумя версиями файла, не открывая внешний diff-инструмент.*

**Решение:**

```bash
vim -d file1 file2
```

Запускает Vim сразу в diff-режиме с двумя окнами рядом, подсвечивая отличающиеся блоки. Тот же эффект без выхода из уже открытого Vim — вручную:

```
:vsplit другой-файл
:diffthis
```

выполненное в обоих окнах (`:diffthis` в каждом из них).

## Сценарий 4: Быстро найти файл в большом проекте

*Как разработчик, я хочу открыть нужный файл в проекте с сотнями файлов, не вспоминая точный путь.*

**Решение:** вместо `:e` с ручным набором пути — fuzzy finder, встроенный в LazyVim (Snacks/Telescope): комбинация по умолчанию открывает поиск файлов по имени, вторая — `live_grep` по содержимому через `ripgrep`. Печатается часть имени или часть текста — список сужается на лету, с превью содержимого. Тот же принцип, что `:b <имя>` + Tab для буферов из [[bufery-okna-vkladki|туториала про буферы]], только по всему проекту, а не только по уже открытым буферам.

## Сценарий 5: Держать несколько конфигов Neovim и выбирать нужный

*Как разработчик, я хочу иметь отдельно «голый» Neovim-конфиг для экспериментов и рабочий LazyVim-конфиг, и быстро выбирать между ними при запуске.*

**Решение:** реальная shell-функция `vv()`, уже используемая в этой настройке (`frolov-center/documents/configs/zsh/files/functions.sh`):

```sh
vv() {
	# Предполагает, что все конфиги лежат в ~/.config/nvim-*
	local config=$(fd --max-depth 1 --glob 'nvim-*' ~/.config | fzf --prompt="Neovim Configs > " --height=~50% --layout=reverse --border --exit-0)

	[[ -z $config ]] && echo "No config selected" && return

	NVIM_APPNAME=$(basename $config) nvim
}
```

Идея: каждый конфиг — отдельная папка `~/.config/nvim-<имя>`, `NVIM_APPNAME` указывает Neovim, какую из них использовать при запуске. `vv` в шелле fuzzy-подбирает нужную папку через `fzf` и запускает Neovim именно с этим `NVIM_APPNAME`. Конфиги полностью изолированы друг от друга — один эксперимент не может случайно сломать рабочий.

## Сценарий 6: Прыгнуть в проект `~/Documents/2026` прямо из редактора

*Как разработчик, я хочу перейти к работе над другим проектом, не выходя из уже открытого Neovim в шелл и обратно.*

**Решение:** keymap `<leader>fp`, разобранный целиком в [[konfig-plaginy-lsp-format|туториале про устройство LazyVim]] — fuzzy-подбор папки верхнего уровня через `fd`, `vim.cmd.cd()` в неё и сразу открытие file picker в новом корне. Один keymap вместо связки «выйти из Neovim → `cd` в шелле → снова `nvim`».
