# Установка Neovim и LazyVim с нуля

Уровень сложности: ~15/100 — само по себе это просто установка пакетов, но осмысленный следующий шаг она составляет только после того, как отработаны голые движения Vim. Нужен терминал и права на установку ПО.

**Предполагается:** уверенное владение основами Vim (режимы, операторы, буферы) — [[bufery-okna-vkladki|буферы, окна и вкладки]]. Учиться сразу на LazyVim можно, но тогда IDE-обвязка (автодополнение, LSP-подсказки) маскирует то, что на самом деле происходит на уровне голых команд. Дальше — [[konfig-plaginy-lsp-format|LazyVim изнутри]].

## Зачем LazyVim, если Vim и так работает

LazyVim — заранее сконфигурированный дистрибутив для Neovim: менеджер плагинов, LSP, автодополнение и готовые плагины «из коробки», без сборки конфигурации с нуля. Все команды и мышление из предыдущих туториалов остаются теми же — LazyVim не меняет Vim-движения, он добавляет поверх них IDE-слой.

## Установка стека (Linux Mint / Debian, через Homebrew)

Реальная последовательность команд, которой ставился этот стек:

```bash
sudo apt install build-essential procps curl file git
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Добавить `brew` в `PATH` (после установки скрипт печатает точную строку, обычно она такая):

```bash
echo 'eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc
source ~/.bashrc
```

Поставить весь стек одной командой:

```bash
brew install neovim lazygit lazydocker ripgrep fzf
```

Что тут за чем:
- **neovim** — сам редактор.
- **ripgrep** — быстрый поиск по тексту, на нём построен `live_grep` в Telescope/Snacks.
- **fzf** — fuzzy-поиск, тот же принцип, что у fuzzy-finder внутри LazyVim, но для шелла.
- **lazygit** / **lazydocker** — терминальные TUI для git и Docker, не обязательны для самого LazyVim, но обычно ставятся в комплекте.

`lazydocker` нужен Docker — его Homebrew не ставит:

```bash
sudo apt install docker.io
```

## Сам LazyVim

```bash
mv ~/.config/nvim ~/.config/nvim.bak 2>/dev/null
git clone https://github.com/LazyVim/starter ~/.config/nvim
rm -rf ~/.config/nvim/.git
nvim
```

- `mv ... nvim.bak` — безопасная страховка: если старый конфиг уже был, он не потеряется, а просто отъедет в сторону.
- `rm -rf ~/.config/nvim/.git` — отвязать клонированный starter от апстрима. После этого `~/.config/nvim` — обычная папка, а не git-репозиторий starter'а: можно свободно класть туда свои файлы и коммитить их в свой собственный репозиторий, не путаясь с историей шаблона.
- Первый запуск `nvim` автоматически подтянет и установит все плагины из lazy.nvim.

## fzf в шелл

```bash
$(brew --prefix)/opt/fzf/install
```

Добавляет fzf-биндинги прямо в шелл (например `Ctrl-r` — fuzzy-поиск по истории команд), отдельно от того, что LazyVim использует свой fuzzy finder внутри редактора.

## Проверка, что всё встало

Внутри `nvim`:

```
:LazyHealth
```

покажет, все ли зависимости на месте. Затем:

```
:Mason
```

и установить через него `intelephense` (LSP для PHP) и `prettier`/`eslint` (форматирование и линтинг) — или любые другие сервера под свой стек.

## Проверка себя

С нуля (или в отдельном `NVIM_APPNAME`-конфиге, чтобы не трогать рабочий) повторите шаги выше, откройте `nvim`, дождитесь установки плагинов, выполните `:LazyHealth` и убедитесь, что нет критичных ошибок.
