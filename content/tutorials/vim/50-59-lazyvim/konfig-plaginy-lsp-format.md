# LazyVim изнутри: свои плагины, LSP, форматирование и keymaps

Уровень сложности: ~40/100.

**Предполагается:** LazyVim установлен и запускается — [[neovim-i-lazyvim-s-nulya|установка Neovim и LazyVim]]. Дальше — [[scenarii-primeneniya-vim-lazyvim|сценарии использования]].

## Свои плагины отдельно от ядра

Пользовательские спеки плагинов размещаются в `~/.config/nvim/lua/plugins/` — каждый файл возвращает таблицу спецификаций lazy.nvim и подхватывается автоматически. LazyVim спроектирован так, чтобы пользовательские настройки жили отдельно от ядра: это позволяет безопасно обновлять сам LazyVim, не рискуя потерять свои правки при `:Lazy sync`.

Отключить встроенный плагин, не удаляя его физически:

```lua
return {
  { "плагин/который-не-нужен", enabled = false },
}
```

## `opts` мержится, `config` заменяет

Ключевое отличие двух способов настройки плагина в спеке:

- **`opts`** мержится с дефолтной таблицей LazyVim **рекурсивно** — можно переопределить только нужные поля, остальное останется дефолтным.
- **`config`** полностью заменяет функцию настройки — дефолтные значения LazyVim теряются целиком, настраивать нужно всё самому.

Если нужно дописать элемент в список внутри `opts` (например, добавить источник автодополнения), не перезаписывая остальные — `opts` объявляют функцией:

```lua
return {
  "плагин",
  opts = function(_, opts)
    table.insert(opts.sources, { name = "мой-источник" })
  end,
}
```

Обычная табличная форма `opts = { sources = {...} }` в этом случае затёрла бы весь список целиком вместо дополнения.

## Готовые наборы: `:LazyExtras`

`:LazyExtras` включает готовые бандлы под конкретный стек (`lang.go`, `coding.copilot` и т.д.) без ручной сборки конфига с нуля. Выбранные extras сохраняются в `lazyvim.json`.

## Ленивая загрузка: `VeryLazy`, `ft`, `cmd`, `keys`

Плагины, не нужные сразу при старте, вешают на отложенную загрузку — отсюда и «Lazy» в названии:

- **`VeryLazy`** — событие, которое LazyVim выдаёт после отрисовки первого буфера; хорошее место по умолчанию для «не срочных» плагинов.
- **`ft`** — загрузить при открытии файла определённого типа.
- **`cmd`** — загрузить при первом вызове команды.
- **`keys`** — загрузить при первом нажатии заданной комбинации.

Отложенная загрузка напрямую ускоряет старт Neovim — большинству плагинов не нужно быть готовыми в первую миллисекунду.

## Убрать дефолтный keybind LazyVim

В `keys`-спеке нужного плагина указать тот же бинд со значением `false` вместо функции:

```lua
return {
  "плагин",
  keys = {
    { "<leader>xx", false }, -- отключить дефолтный бинд
  },
}
```

## LSP, форматирование, линтинг

- **LSP-серверы** настраиваются не прямым вызовом `lspconfig`, а через `opts.servers` в спеке `nvim-lspconfig`; настройки конкретного сервера — через `opts.setup`.
- **Автоустановка** серверов и тулов через Mason — ключ `ensure_installed` в `opts` плагина `mason.nvim`.
- **Форматирование** делает `conform.nvim`, форматтеры по типам файлов задаются в `opts.formatters_by_ft`.
- **Линтинг** подключает `nvim-lint`, соответствие типов файлов линтерам — в `opts.linters_by_ft`.

## Где живёт `mapleader`

`lua/config/options.lua` загружается **до** setup самого lazy.nvim, поэтому `mapleader` и глобальные `vim.g`-опции задаются именно там, а не в файлах плагинов.

## Версии плагинов: `lazy-lock.json`

Точные ревизии плагинов фиксирует `lazy-lock.json`. `:Lazy restore` откатывает всё к зафиксированным версиям, `:Lazy update` обновляет плагины и переписывает файл. После `:Lazy sync`, если один из плагинов сломался — первым делом `:Lazy log` (посмотреть changelog обновившихся плагинов на breaking changes) и `:checkhealth`, обычно быстро указывают источник проблемы.

## Диагностика медленного старта: `:Lazy profile`

Показывает время загрузки каждой спеки по отдельности — самый быстрый способ найти конкретный плагин, который тормозит запуск Neovim.

## Живой пример: свой keymap

Реальный кейс из этой настройки: нужен способ быстро прыгнуть в любую папку верхнего уровня `~/Documents/2026` прямо из редактора, не выходя в шелл. Один keymap в `lua/config/keymaps.lua`, который использует встроенный в LazyVim Snacks picker — доустанавливать ничего не нужно:

```lua
vim.keymap.set("n", "<leader>fp", function()
  local dirs = vim.fn.systemlist("fd --max-depth 1 --type d . ~/Documents/2026")
  vim.ui.select(dirs, { prompt = "2026 project > " }, function(choice)
    if not choice then return end
    vim.cmd.cd(choice)
    require("snacks").picker.files()
  end)
end, { desc = "Найти папку в ~/Documents/2026" })
```

Построчно:
- `vim.fn.systemlist(...)` — выполнить shell-команду (`fd`, поиск папок глубиной 1) и получить результат построчно как Lua-таблицу.
- `vim.ui.select(...)` — встроенный в Neovim UI для выбора одного пункта из списка (в LazyVim он рендерится через Snacks/Telescope, если они есть).
- `vim.cmd.cd(choice)` — сменить текущую рабочую директорию Neovim на выбранную папку.
- `require("snacks").picker.files()` — открыть file picker уже в новом корне.

Ничего в этом keymap не требует нового плагина — только то, что LazyVim уже даёт из коробки.

## Проверка себя

Создайте файл `lua/plugins/my-test.lua`, в нём отключите любой один встроенный плагин через `enabled = false`, перезапустите Neovim и убедитесь через `:Lazy` (список плагинов), что он помечен как отключённый.
