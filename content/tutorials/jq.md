# jq на практике — обработка JSON в командной строке

`jq` — это маленький функциональный язык для JSON. Большинство недоразумений с ним — из-за того, что забывают: `jq` работает не со значениями, а с **потоками** значений, а «фильтр» — это функция из потока в поток, а не булев результат. Держа это в голове, остальное собирается быстро.

Примеры для jq 1.6+.

## 1. Поток, а не значение

`jq` по умолчанию читает **поток** JSON-значений, а не одно:

```bash
echo '{"n":1}{"n":2}{"n":3}' | jq '.n'
# 1
# 2
# 3
```

Фильтр применился трижды — по разу на каждый входной объект. Это же объясняет запятую и скобки:

```bash
echo '{"a":1,"b":2}' | jq '.a, .b'     # поток из двух значений: 1, затем 2
echo '{"a":1,"b":2}' | jq '[.a, .b]'   # собрать поток в один массив: [1,2]
```

`[ ... ]` — это «собери всё, что произвёл фильтр внутри, в массив». `map(f)` — ровно `[.[] | f]`.

## 2. Индексация и защита от ошибок

```bash
jq '.user.name'      # на {"user": null} → null (индексирование null даёт null на любой глубине)
                     # на {"user": 5}    → ошибка: Cannot index number with "name"
jq '.["user-name"]'  # ключ с дефисом/точкой; .user-name разберётся как вычитание .user минус name
jq '.items?'         # ? подавляет ошибку, если . нельзя так проиндексировать → пусто вместо падения
```

`?` — главный инструмент устойчивости. Он превращает «ошибка, роняющая всю программу» в «пустой поток».

## 3. Массивы и итерация

```bash
jq '.[]'            # развернуть массив (или значения объекта) в поток элементов
jq '[.[]]'          # собрать обратно — фактически копия
jq '.[-1]'          # последний элемент
jq '.[2:4]'         # срез [2,4): индексы 2,3. Отрицательные тоже работают: .[-2:]
jq '.users[].name'  # на пустом массиве [] → пустой поток (не null, не ошибка)
```

`map(.x)` возвращает **массив**, `.[] | .x` — **поток**. Разница в типе результата, не в логике.

Операторы над массивами работают по значениям, а не индексам:

```bash
echo '[1,2,3,4]' | jq '. - [2,4]'   # [1,3] — разность множеств, удаляет все вхождения
jq 'flatten'                        # рекурсивно разворачивает вложенные массивы
jq 'flatten(1)'                     # только на один уровень
```

## 4. Объекты

```bash
jq '{name: .user.name, id: .user.id}'   # значения — любые фильтры; ключи-идентификаторы без кавычек
jq '{user, id}'                          # сокращение: {user: .user, id: .id}
jq 'to_entries'                          # {"a":1} → [{"key":"a","value":1}]
jq 'from_entries'                        # обратно; понимает key/k/name/Name и value/v
jq 'map_values(ascii_downcase)'          # фильтр к каждому значению — и для объекта, и для массива
```

`map` на объекте — **ошибка**, ему нужен массив. Для объекта — `map_values` или `with_entries`.

## 5. select, recurse, walk

```bash
jq 'select(.age > 18)'          # пропускает . дальше ТОЛЬКО при истинном условии, иначе пусто
jq 'map(select(.active))'       # оставить в массиве только элементы с active == true
jq '[.[] | select(.active)]'    # то же самое
```

`select` — это фильтр, а не булев результат. `map(.active)` вернул бы массив булевых значений, а не отфильтрованный список.

```bash
jq '.. | .id?'                  # .. рекурсивно обходит всё дерево; .id? берёт id, где узел это объект
jq 'recurse(.children[])'       # спуск только по полю children — обход именно дерева узлов
jq 'walk(f)'                    # применить f к каждому узлу снизу вверх, сохраняя структуру
# рекурсивно опустить регистр всех ключей:
jq 'walk(if type=="object" then with_entries(.key |= ascii_downcase) else . end)'
```

## 6. Условия и оператор `//`

```bash
jq '.name // "anon"'   # "anon" подставится, только если .name даёт null, false или ПУСТО
                       # 0 и "" останутся как есть
```

Тонкость с ошибками: `//` **не ловит** ошибку. На входе-строке `.name // "x"` упадёт (`.name` на строке — ошибка), а `.name? // "x"` подставит `"x"` — `?` сначала гасит ошибку до пустого потока.

```bash
jq 'if type == "number" then . * 2 else . end'   # end обязателен; else можно опустить (вернётся .)
jq '.active | not'                               # not — фильтр без аргументов, только через пайп
```

## 7. Строки и регэкспы

```bash
jq '"Hello \(.name)"'          # интерполяция: внутри \( ... ) любой фильтр
jq -r '[.a, .b] | @csv'        # @csv/@tsv ждут ПЛОСКИЙ массив скаляров; вложенное — ошибка
jq '@sh'                       # безопасная подстановка в shell: экранирует и кавычит
jq '.data | @base64d'          # декодировать base64; @base64 — закодировать (это форматтеры, через |)
jq 'test("abc"; "i")'          # булев результат: есть ли совпадение; флаги — отдельным аргументом
jq 'match("re"; "g")'          # объект с деталями (offset, length, captures) или поток при "g"
jq 'gsub("\\s+"; "_")'         # глобальная замена; флаги — 3-м аргументом. Движок — Oniguruma
jq 'ltrimstr("/")'             # срезает префикс только если он есть, иначе no-op
jq 'split(",")'                # массив
jq 'splits(",")'               # поток кусков; split по регулярке требует 2 арг: split("\\s+"; null)
```

## 8. Числа, сортировка, группировка

```bash
jq 'length'        # null→0, строка→кодовые точки, массив→элементы, объект→ключи, число→модуль
                   # булев → ошибка
echo '[]' | jq 'add'          # null, а не 0. Для гарантированного числа: add // 0
jq 'sort_by(.age)'            # по значению фильтра, стабильная; sort — по всему объекту канонно
jq 'unique'                   # убирает дубли И СОРТИРУЕТ — исходный порядок теряется
jq 'group_by(.dept)'         # массив массивов; группы упорядочены по ключу, как в sort_by
jq 'max_by(.score)'          # ЭЛЕМЕНТ с максимальным полем (min_by — минимальный)
```

## 9. Присваивание и пути

Ключевое различие — **против чего вычисляется правая часть**:

```bash
echo '{"a":0,"b":10}' | jq '.a = .b + 1'   # a == 11: правая часть = против КОРНЯ ., значит .b = 10
jq '.tags |= sort'                          # |= : фильтр справа видит ЗНАЧЕНИЕ ПО ПУТИ → массив сортируется
jq '.tags = sort'                           # = : sort применяется к КОРНЮ (объекту) → ошибка
```

В `a op= b` (`+= -= *= /= %=`) правая часть `b` — от корня, `.` слева от операции — значение по пути:

```bash
jq '.items[].price *= .rate'   # .rate берётся с верхнего уровня (корень), .price — по пути
```

Пути как данные:

```bash
jq 'del(.password, .logs[1])'      # несколько путей; индексы в del(.a[1,2]) удаляются без сдвига
jq 'path(.a.b[0])'                 # сам путь как массив ["a","b",0], не значение
jq 'getpath(["a","b",0])'         # обратное: значение по массиву-пути
jq '[paths(type == "string")]'    # все пути к узлам, где условие истинно
```

## 10. reduce, foreach, свои функции

```bash
jq 'reduce .[] as $x (0; . + $x)'        # 0 — начало, . — аккумулятор, $x — элемент; на выходе ОДНО
jq 'foreach .[] as $x (0; . + $x; .)'    # как reduce, но 3-й аргумент выдаётся на КАЖДОЙ итерации
jq 'first(.[] | select(.ok))'            # первый результат генератора, останавливает вычисление
                                         # родственные: limit(n; f), nth(i; f)
jq '.id | IN("a","b","c")'               # эффективная проверка членства скаляра в потоке → булево
jq 'try fromjson catch null'             # или fromjson? — подавить ошибку разбора
def double: . * 2; [.[] | double]        # своя функция; параметры передаются как фильтры:
def pow(e): . ^ e;
```

`contains`/`inside` — про вложенность структур, **не** про членство скаляра в списке; для членства — `IN`.

## 11. CLI-флаги

| Флаг | Что делает |
|------|-----------|
| `-r` | сырые строки на выводе (без кавычек); на числа/объекты не влияет |
| `-c` | компактный вывод, один JSON на строку — для NDJSON и пайпов |
| `-n` | не читать вход автоматически; `.` равен `null`, данные брать через `input` / `inputs` |
| `-s` | `--slurp`: собрать весь вход в один массив (в RAM) |
| `-R` | каждая строка входа как JSON-строка без парсинга; с `-R -s` весь ввод — одна строка |
| `-S` | сортировать ключи в выводе |
| `-j` | raw-вывод без переводов строк |
| `-e` | `--exit-status`: код 0 если последний вывод не false/null; 1 если false/null; 4 если вывода не было |
| `--arg n v` | передать `$n` как **строку** |
| `--argjson n v` | передать `$n` как JSON (число/булево/объект) |
| `--slurpfile n f` | весь файл как массив прочитанных значений в `$n` |
| `--rawfile n f` | содержимое файла как одна строка в `$n` |

Частые грабли:

```bash
jq --arg n 5 '.id == $n'      # НЕ находит: сравнивается .id == "5". Нужен --argjson n 5
jq -n 'reduce inputs as $x (0; . + $x.amount)'   # суммировать поток, НЕ грузя всё в RAM
jq -S -c .                    # детерминированный вывод для диффа двух JSON (порядок ключей не мешает)
```

## 12. jq + остальной шелл

```bash
# curl, где поле data при ошибке API бывает null или отсутствует:
curl -s api | jq '.data[]'              # иногда: Cannot iterate over null
curl -s api | jq '.data[]?'             # устойчиво
curl -s api | jq '.data // [] | .[]'   # тоже

# JSON-логи → TSV для grep/awk:
jq -r '[.time, .level, .msg] | @tsv'    # -r обязателен; @tsv экранирует табы и \n внутри полей

# имя поля из переменной shell — как ДАННЫЕ, не как код:
field=user-name
jq --arg f "$field" '.user[$f]'         # jq ".user.$field" сломается на дефисе и небезопасно

# NUL-разделённый список для xargs -0:
jq -j '.files[] | . + " "'

# переменные окружения:
jq -n 'env.HOME'      # env / $ENV — весь объект окружения на момент старта
```

**Приоритет `//` и `select`.** `.items[] | select(.qty > 0) // "empty"` печатает `"empty"` на **каждый** непрошедший элемент, потому что это `.items[] | (select(...) // "empty")` — поштучно. «Пусто, если никто не прошёл»:

```bash
jq '[.items[] | select(.qty>0)] | select(length>0) // "empty"'
```

## Шпаргалка «почему упало / пусто»

1. `Cannot index X with "y"` → между шагами вклинился скаляр; поставить `?` или `// {}`.
2. `Cannot iterate over null` → `.arr[]?` или `.arr // [] | .[]`.
3. `select` «ничего не вернул» → так и задумано: условие ложно = пустой поток. Оборачивать в `map(select(...))`.
4. `--arg` «не совпадает с числом» → нужен `--argjson`.
5. `@csv`/`@tsv` падает → сначала спроецировать плоский массив: `[.a, .b] | @csv`.
6. `sort`/`sub` падает на `=` → почти всегда нужно `|=`.
7. `add` вернул `null` → пустой массив; `add // 0`.
