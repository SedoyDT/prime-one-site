# ripgrep на практике — от простого поиска до скриптов

`rg` (ripgrep) быстрее `grep -r` и по умолчанию делает разумные вещи: пропускает `.gitignore`, скрытые и бинарные файлы, подсвечивает вывод. Но эти же умолчания иногда «прячут» файл, в котором вы точно знаете, что искомое есть. Этот туториал — про то, как rg решает, что искать, и как это поведение гнуть под задачу.

Все примеры проверялись на ripgrep v13+.

## 1. Что rg вообще смотрит

Прежде чем разбираться, почему `rg` что-то не нашёл, посмотрите на **набор файлов-кандидатов**:

```bash
rg --files                 # все файлы, которые rg будет просматривать с текущими фильтрами
rg --files | rg out.js     # попадает ли конкретный файл в набор
```

Если файла в этом списке нет — дело не в паттерне, а в фильтрах обхода. Почему именно файл исключён, покажет debug:

```bash
rg --debug 'pattern' build/out.js   # какое ignore-правило и в каком файле его отсекло
rg --trace 'pattern' path/          # ещё подробнее, по каждому пути
```

## 2. Ignore-файлы и их приоритет

`rg` читает цепочку ignore-файлов. От низшего приоритета к высшему:

```
core.excludesFile (глобальный)  →  .git/info/exclude  →  .gitignore  →  .ignore  →  .rgignore
```

Более поздний в цепочке побеждает; более глубокий по дереву — тоже. `.ignore` и `.rgignore` не входят в git и удобны для локальных исключений, которые не хочется коммитить.

**Ловушка вне git.** Начиная с v13 `rg` применяет `.gitignore` только когда обнаружил рядом `.git`. В распакованном tarball или просто в каталоге без репозитория `.gitignore` перестаёт действовать. Два способа вернуть:

```bash
rg --no-require-git 'pattern'     # уважать .gitignore без .git
mv .gitignore .ignore             # .ignore/.rgignore действуют всегда
```

**Разовое отключение ignore-правил:**

```bash
rg --no-ignore 'pattern'   # то же: rg -u
```

## 3. Лесенка `-u`

Флаг `-u` накапливается и последовательно снимает фильтры:

| Флаг | Что добавляет |
|------|---------------|
| `-u` | не читать ignore-файлы |
| `-uu` | + скрытые файлы (`--hidden`) |
| `-uuu` | + бинарные файлы (`--binary`) |

`rg -uuu` примерно равно `grep -r`.

**Про `--hidden` и `.git/`.** В `rg` нет отдельного правила для каталога `.git` — он пропускается просто как скрытый. `rg --hidden` в репозитории снимает этот фильтр, и `.git/` начинает просматриваться (много мусора). Обычно `.git/` добавляют в `.ignore`. И наоборот: `--hidden` снимает только фильтр «скрытый» — если скрытый каталог ещё и в `.gitignore` (`.cache/`), понадобится дополнительно `--no-ignore` (или сразу `-uu`).

## 4. Бинарные файлы

По умолчанию на бинарном файле `rg` печатает `Binary file <path> matches` без самих строк.

- `-a` / `--text` — обрабатывать файл как текст, печатать совпавшие строки целиком.
- `--binary` — искать дальше первого NUL-байта, но совпадение сообщать смещением, а не строкой.

Для лога со случайными NUL-байтами, где нужны именно строки, — `-a`.

## 5. Глобы и типы файлов

**Глобы (`-g`):**

```bash
rg -g '*.rs' foo          # по имени файла на любой глубине
rg -g '/src/*.rs' foo     # ведущий / привязывает к корню поиска — только src/ верхнего уровня
rg -g '!target' foo       # ведущий ! исключает каталог target где угодно
rg --iglob '*.jpg' foo    # регистронезависимый глоб (-g регистрозависим: .JPG не поймает)
```

Порядок глобов важен — **побеждает последний совпавший**:

```bash
rg -g '!*.min.js' -g '*.js' foo   # НЕ работает: '*.js' снова включает *.min.js
rg -g '*.js' -g '!*.min.js' foo   # правильно: сначала включаем, потом исключаем
```

**Типы файлов (`-t` / `-T`):**

```bash
rg -t py foo      # весь встроенный набор глобов типа python: *.py *.pyi *.pyw ...
rg -T test foo    # искать везде, КРОМЕ файлов типа test
rg --type-list    # посмотреть все типы и их глобы
```

`-t py` ≠ `-g '*.py'`: первый подставляет весь набор расширений типа, второй — ровно одно.

**Свой тип на один запуск:**

```bash
rg --type-add 'web:*.{html,css,js}' -t web foo
```

`--type-add 'js:*.mjs'` не заменяет встроенный тип `js`, а **добавляет** глоб к нему. Новый тип создаётся, только если имя свободно. Строку `--type-add` нужно повторять при каждом вызове — или прописать в конфиг (см. §10).

## 6. Регулярки: движок и его границы

Движок по умолчанию — Rust `regex`, он **гарантирует линейное время** и потому не поддерживает обратные ссылки и lookaround:

```bash
rg '(\w+) \1'          # ошибка: backreference не поддерживается
rg -P '(\w+) \1'       # -P / --pcre2 переключает на PCRE2: \1, (?=...), (?<=...) работают
```

Цена `-P` — бэктрекинг PCRE2 на «злом» паттерне вроде `(a+)+$` может уйти в экспоненциальное время. Дефолтный движок так не умеет.

Полезное:

```bash
rg -F 'a.b[c]*'        # --fixed-strings: весь паттерн буквально, ничего не экранировать
rg -Fw error           # -w навешивает границы слова даже поверх -F: поймает error, не errors
rg -e foo -e bar       # несколько альтернатив без склейки через | (логическое ИЛИ)
rg -f patterns.txt     # список паттернов из файла
```

## 7. Регистр

Дефолт `rg` — **регистрозависимый**.

```bash
rg -i foo       # без учёта регистра
rg -S foo       # smart-case: без учёта, если паттерн весь в нижнем регистре, иначе с учётом
rg -s Foo       # строго с учётом — перебивает -i и -S из конфига
```

## 8. Многострочный поиск

```bash
rg 'foo\nbar'              # НЕ найдёт: по умолчанию совпадение не пересекает \n
rg -U 'foo\nbar'           # --multiline: совпадение может охватывать несколько строк
rg -U '<div>.*</div>'      # всё ещё не через перевод строки: . не матчит \n даже с -U
rg -U --multiline-dotall '<div>.*</div>'   # теперь да; альтернатива — префикс (?s) в паттерне
```

## 9. Формат вывода

В терминале rg группирует по файлам (`--heading`: имя файла заголовком, ниже `номер:строка`). В пайпе переключается на grep-стиль `файл:номер:строка` (`--no-heading`).

```bash
rg --vimgrep foo               # файл:строка:столбец:текст, одна запись на каждое совпадение
rg -o 'key=\w+'                # --only-matching: только совпадения, по одному на строку
rg -c foo                      # число совпавших СТРОК в файле
rg --count-matches foo         # общее число совпадений (больше, если в строке их несколько)
rg -c --include-zero foo       # включить в вывод и файлы с нулём совпадений
rg --color=always foo | less -R   # сохранить подсветку в пайпе (по умолчанию --color=auto её гасит)
```

**Контекст:**

```bash
rg -C 2 foo          # 2 строки до и после
rg -A 3 -B 1 foo     # раздельно: 3 после, 1 до
```

Между несмежными группами `rg` вставляет разделитель `--` (меняется через `--context-separator`); перекрывающиеся окна сливаются.

## 10. Замена в выводе (файлы не трогаются)

`rg` **никогда не пишет в файлы**. `-r` меняет только текст в выводе — это инструмент предпросмотра, не редактирования.

```bash
rg 'v(\d+)' -r 'ver$1'              # группа как $1 или ${1}
rg '(\w+)' -r '${1}_suffix'         # ОБЯЗАТЕЛЬНО скобки: $1_suffix читается как имя группы "1_suffix"
rg 'pat' -r 'repl' --passthru       # sed-подобное превью: печатает и несовпавшие строки без изменений
```

Литеральный доллар — `$$`.

## 11. Сжатые файлы и препроцессор

```bash
rg -z 'pattern'                              # прозрачно ищет внутри .gz .bz2 .xz .lz4 .zst и др.
rg --pre pdftotext --pre-glob '*.pdf' foo    # произвольный препроцессор, rg ищет в его stdout
```

`-z` умеет только архивные форматы; для PDF/docx/чего угодно — `--pre` с ограничением через `--pre-glob`.

## 12. Обход и производительность

```bash
rg -L foo               # --follow: идти по символическим ссылкам (по умолчанию нет; есть защита от циклов)
rg --max-filesize 1M foo   # пропускать файлы крупнее порога
rg --max-depth 2 foo       # ограничить глубину рекурсии
rg -j1 foo                 # одна нить — для честных замеров (по умолчанию -j0, автоопределение)
```

`--sort path` / `--sortr` **отключает параллелизм**: обход становится однопоточным ради детерминированного порядка вывода. На большом дереве это заметно медленнее.

## 13. rg в скриптах

```bash
rg -q pattern && echo "нашлось"   # -q: молча выйти на первом совпадении; код 0 = есть, 1 = нет
```

`rg -q` в условии `if` лучше, чем `rg pattern > /dev/null`: завершается сразу на первом совпадении, не обходит остальное дерево, не форматирует вывод.

**Коды возврата:** `0` — есть совпадения, `1` — нет, `2` — реальная ошибка. В скрипте с `set -e` отсутствие совпадений (`1`) уронит скрипт — этот случай нужно обрабатывать отдельно:

```bash
rg pattern || true
# или
if rg -q pattern; then ... fi
```

**Списки файлов для пайпа** — через NUL, чтобы не ломаться на пробелах:

```bash
rg -l -0 foo | xargs -0 sed -i 's/foo/bar/g'   # -l0 тоже можно слитно
```

## 14. Конфиг

Переменная `RIPGREP_CONFIG_PATH` указывает на файл — один аргумент на строку, комментарии с `#`:

```
# ~/.config/ripgrep/config
--smart-case
--hidden
--glob=!.git
--type-add=web:*.{html,css,js}
```

`rg --no-config` игнорирует этот файл для конкретного запуска.

## Шпаргалка «почему не нашлось»

1. `rg --files | rg <имя>` — файл вообще в наборе?
2. Нет → `rg --debug 'pat' <файл>` — какое правило отсекло.
3. Файл в `.gitignore`, а `.git` рядом нет → `--no-require-git`.
4. Скрытый → `--hidden` (или `-uu`).
5. Бинарный → `-a`.
6. Не тот тип → проверить `-t`/`-T` и порядок `-g`.
7. Паттерн через `\n` → `-U` (+ `--multiline-dotall` для `.`).
8. Регистр → `-i` или `-S`.
